#+TITLE: Personal Machine Provisioner

Ansible playbook to provision personal machines: the personal Mac, Ubuntu, and Debian. The work Mac is deliberately out of scope — see =~/.dot-files/ISA.md=.

* Requirements

  1. python / pip[x]
  2. ansible

  #+begin_src shell
    pipx install ansible-core
    ansible-galaxy collection install -r requirements.yml
  #+end_src

* Host groups

  - =[mac]= — the personal Mac. Runs locally (=ansible_connection=local=).
  - =[ubuntu]= / =[debian]=, grouped under =[linux:children]= — remote personal Linux boxes, reached over SSH via =~/.ssh/config= host aliases. Fill in real =ansible_host=/=ansible_user= entries in =inventory= once a machine is reachable.
  - =[personal:children]= (=mac= + =linux=) — everything this playbook's cross-platform play targets. Despite the name it includes work Linux boxes like =s76=; what keeps those lean is the feature groups below.

** Feature groups

  Every Linux host gets the base: core apt packages, mise, the base Stow packages, zsh, Nerd Fonts, GNOME preferences. Anything beyond that is opt-in by listing the host under a feature group in =inventory=:

  - =[personal_extras]= — personal apps and tools (restic, syncthing, graphics, multimedia, Krew), plus the extra Stow packages in =group_vars/personal_extras.yml= (=mise-extras=, =ghostty=, =yt-dlp=). Keep work machines out of it.
  - =[electron_dev]= — OS prerequisites for Electron/JS work. Node itself comes from mise.
  - =[vm_host]= — KVM/libvirt and virt-manager for QA virtual machines.

  A work QA box like =s76= is =[debian]= + =[electron_dev]= + =[vm_host]=, and nothing else.

* What each role does

  - =common= — installs mise (cross-platform tool-version manager), the one thing every personal machine needs regardless of OS.
  - =linux= — base apt packages (build tools, git, Emacs, stow, zsh). Runs against all =[linux]= hosts.
  - =linux_user= — per-user base setup: zsh as login shell, Nerd Fonts. Runs against all =[linux]= hosts.
  - =dotfiles= — clones this repo, stows =dotfiles_stow_packages_base= plus any =dotfiles_stow_packages_extra= a group adds, then runs =mise install=. Runs against all =[linux]= hosts.
  - =personal_extras= — personal apps and Krew. Runs only against =[personal_extras]=.
  - =electron_dev= — Electron's runtime libraries, =xvfb= for headless test runs, and the tools electron-forge's deb maker needs. Runs only against =[electron_dev]=.
  - =vm_host= — KVM/libvirt host setup; see /QA virtual machines/ below. Runs only against =[vm_host]=.
  - =mac= — Homebrew taps/formulae/casks (folded in from the old =bootstrap-mac.sh=). Runs only against =[mac]= hosts.
  - =gnome_desktop= — the GNOME preferences worth keeping from the old =gconf-settings.sh=: Caps Lock as an extra Ctrl, window buttons on the left, and the system-wide dark style (GNOME Terminal and Wave follow it). Runs against all =[linux]= hosts as the login user.

  Rust, direnv, fzf, bun, and Starship are mise-managed everywhere and intentionally absent from both the =linux= and =mac= roles — mise is the single source of truth for those, not apt or brew.

  mise's toolset is split the same way as the roles: =mise/.config/mise/config.toml= is the base every machine gets, and the =mise-extras= Stow package adds =~/.config/mise/conf.d/extras.toml= (mise merges every =conf.d/*.toml= into the global config). A host without =mise-extras= stowed never installs those tools.

* Provisioning a fresh Debian host

  1. Install Debian with the GNOME desktop and "SSH server" selected in tasksel. Leave the root password blank so the installer locks root and gives your user =sudo=. On a laptop, pick "Guided, use entire disk with encrypted LVM".
  2. From the Mac, add an =~/.ssh/config= alias for the host and copy your key: =ssh-copy-id <alias>=.
  3. Add the alias to =[debian]= in =inventory=, plus whichever feature groups it should have.
  4. Run the playbook against it:

  #+begin_src shell
    ansible-playbook -i inventory --ask-become-pass playbook.yml --limit s76
  #+end_src

  Log out and back in afterwards so the zsh login shell and the =libvirt=/=kvm= group memberships take effect.

* QA virtual machines

  =vm_host= sets up the host and leaves guests to you, since each QA round wants different ones:

  - The =default= libvirt network: NAT on =virbr0=, =192.168.122.0/24=, DHCP from libvirt's dnsmasq, autostarted. Guests reach the internet and the host; the LAN can't reach the guests.
  - An =isos= storage pool at =/var/lib/libvirt/isos=, group-writable by =libvirt=, so you can download installer ISOs there without sudo. It's outside =$HOME= so qemu can read the files without virt-manager asking to fix ACLs.
  - UEFI firmware (=ovmf=) and a software TPM (=swtpm=), enough for Windows 11 guests.
  - =~/.config/libvirt/libvirt.conf= points =virsh= and =virt-install= at =qemu:///system=, the same daemon virt-manager uses.

  Creating a guest from the CLI (virt-manager's "New VM" wizard does the same thing):

  #+begin_src shell
    curl -L -o /var/lib/libvirt/isos/ubuntu-24.04.iso <ubuntu desktop ISO URL>
    virt-install --name ubuntu24.04 --osinfo ubuntu24.04 \
      --memory 4096 --vcpus 2 --disk size=40 \
      --cdrom /var/lib/libvirt/isos/ubuntu-24.04.iso --network network=default
  #+end_src

  Snapshot a guest right after its OS install (e.g. =virsh snapshot-create-as ubuntu24.04 clean-os=) so every QA round can start from a known-clean state.

  To share a host directory into a guest, add a virtiofs filesystem in the VM's hardware details and enable shared memory under /Memory/; inside the guest, =sudo mount -t virtiofs <target-name> /mnt=.

* Running the playbook

  #+begin_src shell
    ansible-playbook -i inventory playbook.yml --syntax-check
    ansible-playbook -i inventory playbook.yml --limit mac
    ansible-playbook -i inventory --ask-become-pass playbook.yml --limit linux
  #+end_src

** Testing a dotfiles branch on a fresh host

  The =dotfiles= role clones the repo over HTTPS (no SSH key or GitHub
  registration needed on a brand-new machine) and checks out =master= by
  default. To provision against a feature branch instead, override
  =dotfiles_version=:

  #+begin_src shell
    ansible-playbook -i inventory --ask-become-pass playbook.yml --limit xps -e dotfiles_version=mise-bootstrapper
  #+end_src

  The clone is skipped when =~/.dot-files= already exists, so delete a
  stale clone on the host first if it's on the wrong branch.

  On later runs the role fast-forwards the existing clone (=git pull
  --ff-only= on its current branch) so new dotfiles commits reach
  already-provisioned hosts. It skips the pull, with a warning, when the
  host's clone has uncommitted changes.
